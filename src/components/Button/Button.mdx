# Button

The tappable control for triggering an action — booking a bay, confirming a party size,
starting checkout. Reach for it any time the user needs to move something forward.

## Types

<Canvas of={ButtonStories.Types} />

| Variant | Use for |
|---|---|
| Primary | The single loudest call to action on the screen, e.g. "Book a bay". Only one per screen. |
| Secondary | A supporting action next to a Primary, e.g. "View venue" beside "Book a bay". |
| Tertiary | A lower-emphasis, outlined action, e.g. "Change party size" inside a form. |
| Ghost | The lowest-emphasis action, no border at all, e.g. an inline "Skip this step". |
| Success | Confirms a positive outcome, e.g. "Confirm booking". |
| Error | A destructive or negative action, e.g. "Cancel reservation". |
| Warning | An action that needs caution, e.g. "Release held tee time". |
| Info | A neutral informational action, e.g. "Learn about membership". |

---

## Sizes

<Canvas of={ButtonStories.Sizes} />

`default` is the only size for web and mobile. `large` is a Kiosk-only touch target
(326×104px in the source Figma file) — never use it in a web or mobile layout.

---

## Icons

<Canvas of={ButtonStories.Icons} />

`leadingIcon` and `trailingIcon` are instance-swap slots that sit before or after the
label; icons should inherit their color from the button rather than carrying a hardcoded
fill. `onlyIcon` visually hides the label but keeps it in the DOM as screen-reader-only
text, so always pass a real, descriptive `children` string even in icon-only buttons.

---

## States

<Canvas of={ButtonStories.States} />

Real states come from real CSS: `:hover`, `:focus-visible` and `:active`, plus the native
`disabled` attribute. `forceState` pins one of these open so this page can show every
state at once in a static screenshot — it must never be used in application code.

## Do / Don't

**Do**
- Use a verb phrase label, e.g. "Book a bay" rather than "Bay".
- Keep one Primary button per screen — it's the single loudest call to action.
- Let icons inherit color rather than hardcoding an icon fill.

**Don't**
- Use `forceState` in application code — it exists only for documentation screenshots.
- Disable a button without explaining why nearby, e.g. helper text or a tooltip.

---

## Accessibility

Button renders a real `<button type={htmlType}>`, so Enter/Space activation, tab focus
order and the `disabled` attribute all come from the browser for free. Focus is always
visible via `:focus-visible` (or `forceState="focus"` for documentation), which draws a
`--pk-sys-border-focus` outline offset from the pill edge. When `onlyIcon` is set, the
label text is not removed from the DOM — it's kept as visually-hidden text
(`.pk-button__label--sr-only`) so screen readers still announce a real label, which is
why `children` should always be a descriptive string even on icon-only buttons.

## Figma parity

Source: file `x40IO8pltwoAFiVkBZEUzT`, node `10408:4635` (component set `10443:108219`,
98 variants). Verified 2026-09-10 against a full Figma snapshot capture; three
mismatches from an earlier implementation were corrected:

- **Success/Error/Warning/Info are a soft pill, not a solid CTA.** The source file
  fills these with the pale `-bg` token and labels them with the dark `-text` token —
  not a saturated background with a white label as previously coded. Hover/Pressed
  backgrounds were already correct.
- **Tertiary's hover/pressed is a solid fill, not a tint.** The source file swaps in
  the full-opacity `-hover`/`-pressed` Magenta step (with the label going near-white)
  rather than a `color-mix()` wash. Ghost/Link, despite looking similar to Tertiary,
  binds a completely different token family — Cool-Blue text and a neutral
  black-tint hover/pressed wash, styled like a hyperlink rather than a mini-Tertiary.
- **`inverse` previously did nothing for Secondary or the Feedback types.** Figma
  defines dedicated `Interactive/Secondary-Inverse/*` and `Feedback-Inverse/*` token
  groups for these — not just a text-color swap — so both now flip to their own
  fill/label recipe when `inverse` is true. `Disabled` also has its own
  `Interactive/Disabled Inverse/*` white-alpha group (vs. the plain black-alpha
  Disabled tokens) for Primary/Secondary/Tertiary.

Disabled only has a distinct Figma treatment for Primary, Secondary and Tertiary,
so Success/Error/Warning/Info/Ghost fall back to Tertiary's disabled styling rather than
inventing a new one. `inverse`'s default-state override still only touches Tertiary and
Ghost directly — their default Midnight Purple text and border would disappear on a
dark surface — while Primary keeps no inverse treatment at all (Figma defines none),
and Secondary/Feedback's inverse recipes are defined next to their base rules rather
than in the shared inverse block.
