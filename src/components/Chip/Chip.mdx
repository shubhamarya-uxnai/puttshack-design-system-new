# Chip

A small pill-shaped label for tagging and filtering content — filter tags, status labels, category tags. Comes in three variants: a dark neutral pill, a brand-tinted promo pill, and an avatar chip that pairs a person's photo or initials with a removable label.

## Variants / Types

<Canvas of={ChipStories.Types} />

| Variant | Use for |
|---|---|
| `default` | Neutral filter tags and category labels — the workhorse variant |
| `promo` | Brand-tinted highlight for a promotional label (e.g. "Happy Hour"). Renders sparingly — 1-2 per viewport |
| `avatar` | Tagging content to a person — pairs a leading avatar (`avatarSrc` or `avatarInitials`) with the label, plus an optional remove control |

---

## States

<Canvas of={ChipStories.States} />

The chip body itself is non-interactive and has no states. The avatar variant's remove button, when rendered, has real `:hover`, `:focus-visible` and `:active` CSS — `forceState` exists only so this page can show all four side by side in one static screenshot, and must never be used in application code.

---

## Avatar image vs. initials fallback

<Canvas of={ChipStories.AvatarSource} />

Pass `avatarSrc` for a real photo. Without it, the avatar circle falls back to `avatarInitials` on a translucent tint — useful while a photo is loading or when one was never uploaded.

---

## Removable avatar chip

<Canvas of={ChipStories.Removable} />

The trailing × button only renders on the avatar variant, and only when `onRemove` is passed. Chips don't assume a remove handler always exists — a read-only avatar tag (e.g. "assigned to") and a removable one (e.g. a filter you can clear) use the exact same component.

## Do / Don't

**Do**
- Use for filter tags, status labels, category tags
- Reach for the avatar variant when a tag needs to be traced to a specific person (a party member, a staff assignment)

**Don't**
- Use chips as primary navigation — use Tabs instead
- Overuse the promo variant — it's a highlight, not a default state

---

## Accessibility

The chip body renders as a plain `<div>` — it's a styled label, not an interactive widget, so it carries no role or tabindex. The only interactive part is the avatar variant's remove control, which is a native `<button type="button">` with focus handled natively by the browser and a real `:focus-visible` outline. Its `aria-label` reads "Remove {label}" when the label is a plain string, falling back to "Remove" otherwise, and the × glyph itself is `aria-hidden` so screen readers announce only the button's label.
