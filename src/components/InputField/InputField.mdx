# Input Field

A labeled text input for forms and booking flows — guest details, tee times, promo codes, venue
search. Reach for it any time a user needs to type a value, rather than pick from a fixed set
(that's Chip or Radio Button territory).

## Variants

<Canvas of={InputFieldStories.Variants} />

The `State` variant covers the field's full lifecycle:

| State | When to use it |
|---|---|
| `default` | Empty or resting, no interaction yet. |
| `typing` | The user has focus in the field right now. In the app this is driven by real `:focus-within`, not something you set by hand — the prop exists mainly for documentation and for building state directly into a design handoff. |
| `typed` | Field has a value and has lost focus. Same border treatment as `default`; the difference is the content. |
| `disabled` | Not editable — pair with a `defaultValue`/`value` when it's showing a locked-in answer rather than an empty field. |
| `error` | Validation failed. Always pair with a `helperText` message explaining what to fix — never rely on the red border alone. |

## States

<Canvas of={InputFieldStories.States} />

Real states are real CSS (`:focus-within` drives the `typing` look automatically) plus the native
`disabled` attribute. `forceState` exists only so this page can pin the real focus ring open for a
static screenshot — it must never be used in application code.

## Inverse

<Canvas of={InputFieldStories.Inverse} />

`inverse` swaps the field onto a dark surface for use on branded/dark backgrounds. It's an
independent axis from `State` — every state has an inverse counterpart in the source Figma
component set.

---

## With icons

<Canvas of={InputFieldStories.WithIcons} />

`leadingIcon` and `trailingIcon` each accept any `ReactNode` and are independently optional — pass
one, both, or neither. Icons are decorative only (rendered with `aria-hidden`); if an icon is
interactive (like a clear or reveal-password button), it needs its own accessible control, which
this component doesn't provide out of the box.

## Do / Don't

**Do**
- Always show a visible label, unless the field is inside a compact search bar.
- Use `required` to mark mandatory fields — never color alone.
- Put format hints or error messages in `helperText` — not both at once; pick whichever is more
  useful for the current state.

**Don't**
- Nest an Input Field inside another Input Field.

---

## Accessibility

The label renders as a native `<label htmlFor>` bound to the input's `id` (auto-generated via
`useId` when you don't pass one), so clicking the label focuses the field. When `state="error"`,
the input gets `aria-invalid`. Whenever `helperText` is present, the input's `aria-describedby`
points at the helper row, so assistive tech announces the hint or error message alongside the
field's value. `required` sets the native HTML `required` attribute in addition to rendering the
"*" marker.

## Figma parity

Source: file `x40IO8pltwoAFiVkBZEUzT`, node `10554:17948` (component set "Input Field",
`10559:11972`, 10 variants: 5 `State` values × `Inverse`).

Two deliberate departures from the Figma spec: the canonical Figma frame is a fixed 374px wide,
but this implementation is `width: 100%` so it drops into a real responsive layout instead of
always measuring exactly 374px. And the source file's own instance-swap property is spelled
"Tailing Icon" (a typo for "Trailing") — the prop is named correctly here as `trailingIcon`.

Most of the layer data captured under this node is documentation/annotation furniture (callout

input row itself, so it wasn't usable to re-derive the row's own border/background per state.
The one confidently-sourced correction from it was the required-asterisk color (magenta, not
error-red, see above) — everything else (all 5 states, `inverse`, `required`, helper text
toggle, and both icon slots) was already correctly implemented and is unchanged.
