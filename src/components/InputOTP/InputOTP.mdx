# Input OTP

A row of single-digit cells for fixed-length codes: OTPs, verification
codes, and PINs. Use it whenever the destination knows the exact code
length up front, never for phone numbers, booking references, or any other
variable-length input.

## Sizes

<Canvas of={InputOTPStories.Sizes} />

`size` (Figma: `Mode`) drives cell dimensions only via `[data-screen]` —
a bigger touch target at each step up, not a different fill or color:

| Size | Cell dimensions |
|---|---|
| `mobile` | 61 × 72px |
| `desktop` | 90 × 100px (default) |
| `kiosk` | 120 × 160px |

All 3 sizes share the same 12px (`$md`) corner radius, the same pale
`--pk-ref-black-06` fill, and the same 48px digit — confirmed from the
source file, which has no per-mode override for radius or digit size.

---

## Inverse

<Canvas of={InputOTPStories.Inverse} />

`inverse` (Figma: `Color` = Inverse) is an **independent axis from `size`**
— pass it wherever the cells sit on a dark surface, at any of the 3 sizes.
It is not tied to `size="kiosk"`: a kiosk-sized OTP on a light surface uses
the same default fill as mobile/desktop, and a mobile-sized OTP can be
inverse too.

---

## Error state

<Canvas of={InputOTPStories.ErrorState} />

`error` is component-level, not per-cell: on error, every cell takes the
error border together and the whole code clears and refocuses the first
cell — never highlight only the offending cell. Pass `errorMessage` to
render supporting copy below the cells.

---

## Lengths

<Canvas of={InputOTPStories.Lengths} />

`length` sets how many digit cells render (default 6). The Figma source
uses 6 as its visual example; soft guidance caps this around 8 digits for
codes that stay comfortably scannable — `length` itself isn't clamped, but
treat 8 as the practical ceiling rather than reaching for this component on
longer identifiers.

## Tokens consumed

| Token | Used for |
|---|---|
| `--pk-sys-gap-sm` | Gap between label and cell row ("$GAP/Medium", 8px); gap between cells |
| `--pk-ref-radius-md` | Cell corner radius — confirmed the same ("$md") at every size |
| `--pk-sys-text-primary` | Label text color; digit color (default, non-inverse) |
| `--pk-sys-text-inverse` | Label and digit color when `inverse` is true |
| `--pk-ref-black-06` | Default cell fill ("$Surface/Subtle@6%") — no `--pk-sys-surface-*` token lands on this exact tone |
| `--pk-sys-surface-inverse` | Cell fill when `inverse` is true ("$Surface/Inverse@2%") |
| `--pk-ref-border-medium` | Cell border width (transparent by default; colored on `error`) |
| `--pk-sys-font-ui-bold` | Digit font family |
| `--pk-sys-text-magenta` | Caret color — Figma's Active state uses a blinking magenta cursor ("$Text + Icon/Magenta") |
| `--pk-sys-border-focus` | Focus ring (`:focus-visible`) |
| `--pk-sys-error-border` | Cell border color when `error` is true |
| `--pk-sys-error-text` | Error message color |

Cell width/height and the digit font size are pinned as component-tier
variables (`--pk-comp-input-otp-*`) rather than mapped to a `--pk-ref-*`
step: the confirmed cell dimensions (61×72 / 90×100 / 120×160px) fall
between spacing steps, and the 48px digit has no matching named Text
Style — Figma calls it "Headline/X-large", a step that doesn't exist among
this codebase's 17 Text Styles (Headline tops out at Large, 36px).

## Do / Don't

**Do**
- Use for fixed-length digit entry: OTPs, verification codes, PINs (roughly up to 8 digits).
- Label the group as a whole with `label` — it describes what the whole code is for, not any single cell.
- Let `onComplete` fire the submit — once every cell is filled the code is ready, no separate confirm button needed.
- Reserve `autoFocus` for screens where the OTP input is the primary or only action — stealing focus elsewhere is disorienting.

**Don't**
- Don't use for phone numbers, booking references, or any other variable-length input — reach for a standard text field with `inputMode="numeric"` instead.
- Don't label individual cells (no "Digit 1", "D2", "D3" visible labels) — the group label is the only label a user sees.
- Don't highlight only the cell that caused an error — error is a whole-component state, and on error all cells clear and refocus the first cell together.
- Don't let the keyboard dismiss between cells on mobile — auto-advance is built to keep focus (and the keyboard) in place through entry.

## Accessibility

Each cell is a real `<input type="text" inputMode="numeric" maxLength={1}>`,
so it inherits native keyboard, autofill, and screen-reader input behavior
rather than emulating one with `<div>`s. The row of cells sits in a
`role="group"` container, labeled via `aria-labelledby` pointing at the
visible `label` when one is passed. Each cell additionally carries its own
`aria-label` ("Digit 1 of 6", etc.) for screen-reader context, separate
from the never-shown-visually per-cell labeling the Do/Don't above warns
against. On error, cells get `aria-invalid` and the message below renders
with `role="alert"` so assistive tech announces it as it appears. Backspace
on an empty cell moves focus back and clears the previous cell; paste (or
OS/SMS autofill delivering the full code into one cell) distributes digits
across the remaining cells from the cursor position.

## Figma parity

Source: file `x40IO8pltwoAFiVkBZEUzT`, component sets `Numeric input`
(node `12960:6294`, the group of cells + Error/Inverse/"Show 8" variants)
and `_Numeric input` (node `12642:82259`, the individual cell — `Color`
Default/Inverse × `Mode` Mobile/Desktop/Kiosk, plus `Cursor`/`Error`/`Number`
booleans), page "⭐ input OTP".

`size` (Mode) and `inverse` (Color) are confirmed as two independent variant
axes on the individual cell, not one combined "device mode" — the previous
implementation conflated them (treating kiosk as always-dark and mobile as
always-bordered), which the source data doesn't support: Default-color cells
use the same pale fill and no border at every Mode, and Inverse can apply at
any size. Cell dimensions (61×72 / 90×100 / 120×160px) and the 48px digit
size are pinned as component-tier variables since neither maps to an
existing `--pk-ref-*` spacing/radius step or a named Text Style — both are
called out in the component's own CSS rather than silently rounded. The
`Cursor` boolean (a visible blinking magenta caret rectangle) is
approximated here with the native input's `caret-color` rather than a
custom-built cursor element — a deliberate simplification, not a gap.
