# Radio Button

A single-selection input for choosing exactly one option from a visible set — tee times,
party sizes, venue picks. Reach for it whenever the options are mutually exclusive and few
enough to show all at once; for longer lists or free-form choice, use a different control.

## Sizes

<Canvas of={RadioButtonStories.Sizes} />

Three discrete circle sizes, matching Checkbox's scale: `mobile` (20px), `desktop` (24px,
default), `kiosk` (32px). Pick the size that matches the screen the flow is built for — these
are not responsive breakpoints, they're separate Figma variants.

---

## Selection style

<Canvas of={RadioButtonStories.SelectionStyle} />

The plain filled dot is the default selected style. "Selected with Tick" swaps in a solid
magenta circle with a white checkmark — use it in contexts where clarity of completion
matters more than a minimal look (e.g. a multi-step booking flow where users need an
unambiguous "this step is done" signal).

---

## States

<Canvas of={RadioButtonStories.States} />

Real states are real CSS (`:hover` / `:focus-visible`) plus the `disabled` attribute —
`forceState` exists only so this page can show every state in one static screenshot, and
must never be used in application code.

---

## Radio groups

<Canvas of={RadioButtonStories.GroupExample} />

RadioButton renders one correct, controlled input — it does not ship a RadioGroup wrapper.
Mutual exclusion is a consumer concern: give every radio in a set the same native `name` (or
drive them from shared controlled state) so selecting one clears the others. Space items
8–12px apart vertically, and pair the group with a visible heading.

---

## Disabled

<Canvas of={RadioButtonStories.Disabled} />

Disabled radios can be unchecked or checked — there's no error/validation status on the
component itself, since validating a radio group (e.g. "you must pick one") happens at the
group or field level, not per-radio.

## Tokens consumed

| Token | Used for |
|---|---|
| `--pk-sys-gap-xs` | Gap between the circle and the label/tooltip text ("$GAP/Small" — Figma's "Small" step is 4px, matching our `gap-xs`, not `gap-sm`); gap between the label and the tooltip icon |
| `--pk-ref-radius-full` | Fully round corners on the circle and the inner mark |
| `--pk-sys-text-primary` | Default (unselected) circle border color ("$Text + Icon/Primary"); plain-dot fill color when checked; label text color |
| `--pk-sys-surface-default` | Default circle fill |
| `--pk-ref-border-thin` | Circle border width ("$Text + Icon/Primary" stroke, weight 1) |
| `--pk-sys-icon-l` | Circle size ("$Icon size/L") |
| `--pk-sys-icon-m` | "Tick" checkmark glyph size (bound to "$Icon size/M"); tooltip icon size (also "$Icon size/M") |
| `--pk-sys-bg-magenta-light` | "Tick" style checked fill ("$Background/Magenta light" — via component-tier `--pk-comp-radio-color-checked`) |
| `--pk-sys-text-inverse` | Checkmark color inside the "tick" style |
| `--pk-sys-text-secondary` | Hover border color; tooltip icon color |
| `--pk-sys-border-focus` | Focus-visible outline color |
| `--pk-ref-border-medium` | Focus ring width |
| `--pk-ref-space-2` | Focus-visible outline offset |
| `--pk-sys-disabled-border` | Circle border color when disabled |
| `--pk-sys-surface-disabled` | Circle fill when disabled + checked |
| `--pk-sys-text-disabled` | Mark, label and tooltip icon color when disabled |
| `--pk-ref-magenta-300` | "Tick" style checked + hover fill (hover-only escalation; not sourced from a `--pk-sys-*` step) |

Label text uses the `pk-text-body-small` text style (Figma: "Body/Small" — not
`pk-text-body-medium`).

`--pk-comp-radio-size`, `--pk-comp-radio-mark-size`, `--pk-comp-radio-tick-size`,
`--pk-comp-radio-label-line-height` and the checkmark mask icon are component-local tokens
with no single `--pk-sys-*` equivalent — see the comments at the top of `RadioButton.css`
for why. The plain-dot mark size (`--pk-comp-radio-mark-size`) is derived as
`circle size − 8px`, matching the confirmed 4px inset on every side of the circle in the
source file, rather than a percentage scale.

## Do / Don't

**Do**
- Pre-select a default option when a safe default exists.
- Use clear, concise labels.
- Group radios under a visible heading.

**Don't**
- Use radio buttons for actions — they're for selection only.
- Nest radio groups inside one another.
- Leave a required group with no default selected.

---

## Accessibility

RadioButton wraps a native `<input type="radio">` inside a `<label>`, so the label, the
tooltip icon, and the circle all sit inside one tap target and clicking anywhere in it
toggles the input. Keyboard focus and arrow-key navigation between grouped radios come from
the browser's native handling of a shared `name` attribute — no ARIA is added or needed
beyond that. Focus is shown with a visible `:focus-visible` outline rather than a color
change alone.
